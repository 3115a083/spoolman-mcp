# Spoolman MCP for Dockge / TrueNAS

Docker wrapper around [Disane87/spoolman-mcp](https://github.com/Disane87/spoolman-mcp), pinned to upstream commit [18b5119](https://github.com/Disane87/spoolman-mcp/commit/18b511912f5d160bedbe0f5ec54217114e0653db). The upstream MIT-licensed server uses the existing Spoolman HTTP API. This repository adds a deployable Streamable HTTP gateway with mandatory API-key protection.

## Features

- All upstream MCP tools, including **read and write tools**. No server-side read-only mode.
- Streamable HTTP at `/mcp` via [mcp-proxy](https://github.com/punkpeye/mcp-proxy) 6.10.0.
- Required `MCP_PROXY_API_KEY` sent by clients in `X-API-Key`.
- Localhost-only host port by default; hardened non-root, read-only container.
- No Spoolman volume mounts, database changes, or changes to the TrueNAS catalog app.

## Quick start

```bash
cp .env.example .env
# Edit .env with your Spoolman URL and a secret generated by: openssl rand -hex 32
docker compose up --build -d
curl -i http://127.0.0.1:18788/ping
```

See [Dockge setup](docs/DOCKGE.md) and [security / ChatGPT constraints](docs/SECURITY.md). **The protected Pangolin URL cannot be added directly to ChatGPT without a compatible authentication integration.** Do not disable Pangolin authentication to work around this.

## Testing

```bash
sh scripts/test-config.sh
docker build -t spoolman-mcp:test .
sh scripts/test-container.sh spoolman-mcp:test
```

Tests initialize MCP only. They do not change real Spoolman inventory. The source is pinned, but the base image is not digest-pinned and transitive npm dependencies of mcp-proxy are resolved at build time. Review and tighten these supply-chain details before strict production use.
